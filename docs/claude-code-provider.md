# Claude Code provider

This optional provider uses the user's own Claude subscription through an installed official Claude Code binary and its own login. It is off by default. macOS and Linux only; Windows is refused.

## Configuration

Endpoint configuration lives in `claude-endpoint.json` next to the auth key file, stored atomically with mode 0600. PUT `{"mode":"endpoint","baseUrl":"https://relay.example","token":"example-token"}` validates and saves it; omitted fields reuse the stored endpoint configuration, except that a stored token is reused only while the base URL keeps its origin (scheme, host and port); a new origin needs its token again. Switching to local or off retains it. Only endpoint streams receive the explicit `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN`; version, auth-status and login probes always use the local allowlist. Tokens never enter server process.env or responses. Endpoint updates save connection settings before credentials and restore prior settings if the credential write fails.

Login alone also inherits DISPLAY, WAYLAND_DISPLAY, XDG_RUNTIME_DIR and DBUS_SESSION_BUS_ADDRESS to open the Linux desktop browser. Login cancellation signals only the direct child; non-exec wrappers may leave descendants running.

All four routes accept only a loopback Host (`127.0.0.1`, `localhost` or `[::1]`, with a port), refuse any Origin other than that same loopback host, require the Origin on PUT, POST and DELETE, and refuse cross-site fetches, all before doing work. Status probes share an in-flight request and cache settled successful results for five seconds; each probe has a ten-second deadline, followed by direct-child SIGKILL after a two-second SIGTERM grace if needed; connection mutations and login exit invalidate them.

Connection settings live in `<LH_DATA_DIR>/claude-code.json` (the default data directory when `LH_DATA_DIR` is unset): `{"mode":"off","executable":null}`. Select `local` to register the provider or `off` to remove it immediately, without restarting. No Claude credential is stored by the app. Endpoint mode uses the same binary with explicit relay credentials.

- `GET /api/claude-code` reports discovery, version, login and registration state. `executable` is the registered or configured path, else the first discovered candidate; `discovered` is a runnable fallback only when an existing registered or configured path differs, with `hint` advising an explicit path update. `version`, `loggedIn`, and `account` describe `discovered` when present, otherwise `executable`. `active` describes actual registration, even when its path is missing.
- `PUT /api/claude-code` with JSON `{"mode":"local","executable":"/example/bin/claude"}` validates the binary and saves the connection. Omitting `executable` uses the saved path or first discovered candidate. `{"mode":"off"}` disables it while retaining the saved path. Committed changes return `ok: true`, `error: null`, and optional `probeError` diagnostics; failures return a non-2xx status with `error`. Bodies are capped at 64 KiB and validated before the mutation lock.
- `DELETE /api/claude-code/endpoint` clears the endpoint credential file. When endpoint mode is selected, it switches to off, retaining the saved executable. Successful deletion also returns `ok: true`, `error: null`, and optional `probeError`, independently of probe success.
- `POST /api/claude-code/login` with `Content-Type: application/json` starts `claude auth login --claudeai`. Claude opens the browser; the response also supplies its HTTPS login URL. A successful login child that exits without a URL returns `login: {state: "idle"}`. Poll GET for login status. A new login replaces the previous child, and login expires after ten minutes.

Discovery checks the saved path, PATH, standard user and system install directories, and nvm versions newest first. Symlinks deduplicate by target while retaining the first discovered path so neighboring node executables and automatic updates work.

A non-empty real launch-env `LH_CLAUDE_CODE_EXECUTABLE` still wins over settings, reports `envOverride: true`, and makes PUT return 409. Its stat-only boot decision stays cached until restart, including rejections; the status GET names the reason in its `error` (for example `Claude Code executable was rejected (not an absolute path)`), which the Settings Claude card shows. A value supplied only by `auth.json` is ignored with one private warning; saved settings still apply. `LH_IGNORE_ENV_KEYS=1` rejects a real override as before. Saved local paths receive stat checks at boot without spawning any process; runtime validation requires `--version` to identify Claude Code. While the provider is off, a Claude Code selection shows the "Claude isn't turned on" notice where key setup would open, and sending opens the model picker when another provider is connected.

## Request lifecycle

1. Auth resolves to `{auth: {}}` with no API key; the provider returns a stream synchronously and continues detached.
2. Fold the current system prompt, tools, and non-system history from the transcript.
3. Split: a trailing user run supplies the prompt's text/image blocks; a trailing tool result uses `CONTINUE_TEXT`; anything else errors with “nothing to send” and spawns nothing.
4. Convert prior history with `mcp__custom-tools__<name>` names, merged parallel results, and separate continuation records; replay signed thinking only from `claude-code` messages.
5. Write a per-call session file using the fixed LH cwd (`PATHS.data/claude-code/cwd`, resolved to its realpath) and `~/.claude`, injectable for tests.
6. Acquire a FIFO, abort-aware child slot: `LH_CLAUDE_CODE_MAX_CHILDREN`, default 4.
7. Dynamically load the SDK on first use and call `query()` with the forced options in the safety table, `maxTurns: 1`, and `persistSession: false`.
8. Map start, text/thinking/tool-call deltas, ends, and usage; strip known served-name prefixes and handle restreamed messages and non-streaming fallbacks.
9. With tool calls, close at `message_stop`; without tool calls, wait for `result`, including rate-limit error text. Any Extra Usage signal latches a refusal for this and every later call until restart.
10. Abort interrupts and closes the child, then emits an aborted error with partial output.
11. Finally release the slot and delete the session file; on first use, sweep session files and companion directories older than 1 h within this cwd's Claude project directory.

Server tools execute in the harness and resume in a fresh child with tool results plus `CONTINUE_TEXT`; client tools such as quiz end the run with a placeholder, then the later answer resumes the same way.

## Live sessions (LH-62, opt-in)

The lifecycle above starts a child per model call, so the prompt cache never covers the history: Claude Code ends every request with its own context (a synthetic assistant turn, a system-reminder and the environment block that holds the only message cache breakpoint), which the next call's imported history does not hold, and each call's new session id lets a relay route consecutive calls to different accounts. `LH_CLAUDE_CODE_REUSE=1` keeps one child per conversation instead (`src/agent/claude-code/live.ts`):

- The key is pi's `sessionId`: the chat id for the prober, teacher and practice agents, one id per run for a sub-agent. A call without one runs one-shot as above, and so does a second call while the conversation's child is busy.
- A call continues the child when the child is idle, the model, effort, system prompt, tools and child environment (the endpoint address and token among it) are unchanged, and the transcript extends exactly what the child has seen. Results for the tool calls it is parked on answer those MCP calls in-process; a new learner run goes into its streaming input. The child runs without `maxTurns`, and its trailing frames from an earlier call are dropped by message id. Its usage is counted per request, because its result frame sums every request since its last input.
- Anything else closes the child and starts a new one from an import of the record, which costs one cache rebuild: an edited or compacted history, an over-context recovery (LH-40), a model, effort, prompt, tool or credential change, an error or aborted call (an abort after the input was delivered always closes the child), a tool result over 80,000 characters or an error result with images, a child that exits, and a server restart. So does a child that went on without pi's results: one that gave a tool call its own error result (input it rejected, a call this server refused or Claude Code cancelled), or that sends any model frame while idle. When such a child is already continuing, its echo of a result pi never sent starts the call over on a new child from the record.
- A live child holds its slot until it closes. `LH_CLAUDE_CODE_IDLE_MS` (default 600000, 10 minutes, at most a day) closes an idle child, including one parked on a question the learner has not answered yet; Claude Code's timeout for a parked call is set past it (at least an hour). When every slot is taken, or others already wait, a new conversation first evicts the least recently used idle child. A child that goes idle while others wait for a slot yields it after 2 seconds if anyone still waits then. A sub-agent run frees its child when the run ends (`src/agent/run-session.ts`). Server exit closes every child.
- The server log says `claude-code: live session started (new|replaced)` and `claude-code: live session closed (<reason>)`.
- No SDK contract covers the in-process tool-result path (toolUseId pairing, ack ordering, the post-tool drain). `tests/e2e/claude-code-session-reuse.e2e.ts` proves LearnHarness's side against a stub binary; the real binary needs the live re-measure.

The SDK platform binary is never shipped in the desktop payload; the build fails if it is present. The launcher is supplied by the owner.

`LH_MAX_OUTPUT_TOKENS` and `maxTokens` do not cap this provider: Claude Code sets its own output limit. An invalid `LH_MAX_OUTPUT_TOKENS` still fails every engine build, this one included, because it is validated for all providers: set it to an integer >= 1024 or leave it unset. Thinking `off` sends no effort, so Claude Code's default thinking applies. Usage cost shows as unpriced ("—").

Developers who export the variable in their shell will see an extra provider row in `tests/model-catalog.test.ts`-style outputs. Run the test suite with `LH_CLAUDE_CODE_EXECUTABLE` unset.
